# checkq — แดชบอร์ดคิวแพทย์ ณ จุดลงทะเบียน (v3 · 2026-11-19)

## 1. ขอบเขต

| หัวข้อ | ข้อสรุป |
|---|---|
| ใช้เมื่อไร | วันนี้แบบเรียลไทม์ ตอนคนไข้มาลงทะเบียน แล้วเจ้าหน้าที่เลือกแพทย์ |
| คิวของแพทย์ | คนที่มาแล้วและกำลังรอ + หน้าสรุปทั้งวัน |
| นับเข้าช่วงเวลา | ตามเวลามาถึงจริง (ก่อน 08.00 นับเป็นช่วงแรก, 12.xx นับเป็นช่วง 13.00) |
| โควต้า | แพทย์ × คลินิก × ช่วงเวลา **ค่าเดิมทุกวันที่ออกตรวจ** (หน้า "โควต้าแพทย์") |
| เวรรายวัน | ระบบสร้างจากวันออกตรวจประจำให้เอง เจ้าหน้าที่กดเปลี่ยน ออกตรวจ/ลา/ประชุม หรือปิดบางช่วง |
| คลินิกที่ไม่คุมโควต้า | สวิตช์ในหน้า "ตั้งค่าคลินิก" (แนะนำตามคนรออย่างเดียว) |
| ลงแพทย์ใน HOSxP | เจ้าหน้าที่ลงเอง ระบบอ่าน HOSxP อย่างเดียว |
| ผู้ใช้ | SSO กลาง · role `admin` (ทุกอย่าง) / `staff` (คิว, สรุป, เวร, ส่งคนไข้) |

## 2. ข้อมูลระหว่างวันอัปเดตอย่างไร

- ระบบดึง **visit วันนี้ทั้งโรงพยาบาล** จาก HOSxP replica ใหม่ทุก 20 วินาที (`hosxp.cache_seconds`) — ไม่ใช่ดึงครั้งเดียวต่อวัน
- ทุกเครื่องใช้ข้อมูลชุดเดียวกัน (แคชไฟล์ `storage/`) replica โดนไม่เกิน ~3 query/นาที ไม่ว่าเปิดกี่เครื่อง
- หน้าแดชบอร์ดโหลดตัวเลขใหม่เองทุก 30 วินาที (`refresh_seconds`) หยุดชั่วคราวระหว่างเปิด popup
- เวลามาถึง = เวลาลงทะเบียน visit ใน HOSxP → ใช้ตัดสินว่าอยู่ช่วงไหน
- **กันสองจุดลงทะเบียนส่งหมอคนเดียวกันพร้อมกัน:** กด "ส่งไปหมอคนนี้" แล้ว ระบบนับเป็นคิวชั่วคราวของหมอคนนั้นทันที (ทุกเครื่องเห็น) จนกว่า HOSxP จะเห็นคนไข้ หรือครบ `pending_minutes` (10 นาที)

## 3. การแนะนำแพทย์

ไม่ตัดใครออก แต่เรียงเป็นกลุ่ม:
1. ออกตรวจ และโควต้าช่วงนี้ยังเหลือ
2. ออกตรวจ แต่โควต้าช่วงนี้เต็ม (ส่งได้ แต่ระบบเตือน) — ถ้าทุกคนเต็ม ระบบแนะนำคนแรกของกลุ่มนี้พร้อมป้ายเตือน
3. ปิดช่วงนี้ (ประชุม/ออกช้า)
4. ลา / ประชุมทั้งวัน (แสดงสีเทา ไม่มีปุ่มส่ง)

ภายในกลุ่ม: **คนรอตรวจน้อยสุด → ใช้โควต้าช่วงนี้น้อยกว่า → ชื่อ**

## 4. ตาราง (ฐานข้อมูล `checkq`)

| ตาราง | หน้าที่ |
|---|---|
| `cq_clinic` | คลินิก, ใช้ในระบบไหม, คุมโควต้าไหม |
| `cq_slot` | ช่วงเวลา 08/09/10/11/13 |
| `cq_doctor` | รายชื่อแพทย์ (ดึงจาก HOSxP) |
| `cq_plan` + `cq_plan_quota` | โควต้าประจำ: แพทย์ × คลินิก, ห้อง, วันออกตรวจ, โควต้าต่อช่วง |
| `cq_duty` | เวรรายวัน: สถานะ, ช่วงที่ปิด, หมายเหตุ |
| `cq_assign` | บันทึก "ส่งไปหมอคนนี้" (คิวชั่วคราว + ใช้ทำรายงานแนะนำ vs ส่งจริง) |

## 5. หน้าจอ

| หน้า | ใคร | สิ่งที่ทำ |
|---|---|---|
| คิวแพทย์ตอนนี้ `board.php` | staff | แท็บคลินิก (มีตัวเลขรอ), แถบ "ส่งไปที่" แพทย์ที่แนะนำ, ค้นหา HN, การ์ดแพทย์ |
| ส่งไปหมอคนนี้ `assign.php` (popup) | staff | ยืนยัน + HN (ไม่บังคับ) + เตือนให้เลือกใน HOSxP |
| เวรแพทย์ `duty.php` | staff | ปุ่ม ออกตรวจ/ลา/ประชุม, ปุ่มช่วงเวลา (กดปิด/เปิด), หมายเหตุ — บันทึกทันที; ดูวันอื่นได้ |
| เพิ่มแพทย์เข้าเวร `duty_add.php` (popup) | staff | เลือกจากแพทย์ที่มีโควต้าแล้วแต่ไม่อยู่ในเวรวันนั้น |
| สรุปทั้งวัน `summary.php` | staff | แพทย์ × ช่วงเวลา: มาแล้ว/โควต้า, รอ, กำลังตรวจ, ตรวจแล้ว |
| โควต้าแพทย์ `quota.php` + `quota_edit.php` (popup) | admin | เพิ่ม/แก้/ลบ, ปุ่ม "ใส่เท่ากันทุกช่วง", ดึงรายชื่อแพทย์ |
| ตั้งค่าคลินิก `settings.php` | admin | ใช้/ไม่ใช้, คุม/ไม่คุมโควต้า |

## 6. ข้อเท็จจริงจาก HOSxP (ตรวจข้อมูลวันที่ 2026-11-18)

| เรื่อง | ผล | ระบบทำอย่างไร |
|---|---|---|
| "ไม่ระบุแพทย์" | ใช้รหัสแพทย์หลอก `0029` (108 จาก 135 นัด) ไม่ใช่ค่าว่าง | `hosxp.unspecified_doctors` → นับเป็นรอเลือกแพทย์ |
| รหัสคลินิก | อยู่ที่ `clinic_visit` ซึ่งมี**เฉพาะ visit ที่มาตามนัด** (78/78) — visit ไม่มีนัด 208/286 ไม่มีคลินิก | ใช้ `ovst.main_dep` → คลินิก ผ่านตาราง `cq_dep_map` (ตั้งได้ที่หน้าตั้งค่าคลินิก) |
| สถานะ | `ovstost` 01/02 = รอ, อื่น ๆ = ตรวจแล้ว · `cur_dep_busy` เป็น N ทั้งหมด | ยังไม่มี "กำลังตรวจ" จริง |
| คลินิกเพิ่ม | 009 คลินิกติดตามต่อเนื่อง, 024 ยาไปรษณีย์ | เพิ่มใน `cq_clinic` แล้ว |
| คิวห้องตรวจ (2026-11-20) | หน้าจอคิว HOSxP ช่อง "แพทย์" = "คิวพบแพทย์ห้องตรวจ 2 (B)" มาจากระบบคิว `opd_qs_slot.doctor_code` (รหัสแพทย์หลอก 0031/0037/0038/0039/0059 = ห้องตรวจ 1–5, A–E) ขณะที่ `ovst.doctor` ยังว่าง · แต่ละ visit มีคิวจุดซักประวัติก่อน (G/S/DP/...) แล้วคิวห้องตรวจ — ใช้คิวล่าสุด · `call_datetime` = ช่อง "เวลาเรียก" · `opd_dep_queue` **ใช้ไม่ได้** (ห้องไม่ตรงหน้าจอ 5/13 คน) · ห้องตรวจใช้ร่วมหลายคลินิก · 1 ห้อง ≈ 1 แพทย์ต่อวัน (~95%) · ovstost 03 = ตรวจแล้ว แม้หน้าจอคิวยังค้างชื่อ | `cq_room.hosxp_qcode` → คิวล่าสุดของ visit เป็นคิวห้อง = คิวของแพทย์ประจำห้องวันนั้น (`cq_visits()`) นับเข้าคลินิกเจ้าของห้อง · เรียกแล้วแต่ยังไม่ตรวจเสร็จ = กำลังตรวจ |

ยืนยันแล้วกับ HOSxP จริง (PostgreSQL 15.2, 2026-11-19): query visit 25–365 ms, สิ้นวัน `ovstost` เปลี่ยนเป็นตรวจแล้วเกือบทั้งหมด,
`ovst.doctor` ถูกเปลี่ยนจาก 0029 เป็นแพทย์ผู้ตรวจหลังตรวจ · การเชื่อมต่อบังคับ read-only + statement_timeout 8 วินาที
ยังไม่ได้ยืนยัน: `ovstost` เปลี่ยนทันทีหลังตรวจไหม (เทียบหน้าห้องตรวจจริง)
คลินิก `015` จิตเวชฉุกเฉิน เพิ่มแล้ว (ไม่คุมโควต้า) และจับคู่แผนก 009 คลินิกจิตเวชฉุกเฉิน → 015

## 7. สิ่งที่ต้องทำต่อเพื่อเปิดใช้จริง

1. ~~ใส่ query จริงใน `lib/hosxp_sql.php`~~ ใส่แล้ว (2026-11-19) — ยังไม่ได้รันกับ replica จริง
2. ใส่การเชื่อมต่อ replica ใน `config.local.php` → `hosxp.dsn/user/pass` และตั้ง `hosxp.mode = 'live'`
3. ล้างข้อมูลตัวอย่าง: แพทย์ที่ลงท้าย "(ตัวอย่าง)" และโควต้าของแพทย์เหล่านั้น แล้วกด "ดึงรายชื่อแพทย์" ใหม่
4. ลงทะเบียนระบบกับ SSO ตัวจริง และให้ role เจ้าหน้าที่ลงทะเบียน
